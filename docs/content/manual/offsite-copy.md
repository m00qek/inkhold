# Keep a copy away from the server

A backup on the server's own disk survives mistakes, but not the disk dying
or the machine being broken into. Ransomware that encrypts a server encrypts
the backup folder beside it too; Supernote has warned about such attacks on
NAS-hosted private clouds. So copy the backup folder somewhere the server
can't change it.

This page uses [rclone](https://rclone.org), one tool for every destination
below. It assumes a nightly backup already runs, as in
[Back up automatically](@/manual/back-up.md).

## Choose where the copy goes

| Where | rclone remote | What keeps it safe if the server is broken into |
| --- | --- | --- |
| A NAS share (Samba) | `smb` | The NAS's own snapshots |
| Dropbox | `dropbox` | Deleted files can be brought back for 30 days or more, by plan |
| Google Drive | `drive` | The trash, for 30 days, though rclone's key can also empty it |
| OneDrive | `onedrive` | The recycle bin, for 30 days, though rclone's key can also empty it |
| A storage bucket (S3, Backblaze B2) | `s3`, `b2` | Object Lock: nothing can be deleted until the lock runs out |
| Another computer that fetches the copy | `sftp` | The server has no way into it at all |

The server holds rclone's key to every destination but the last one, so
an intruder holds it too. What protects the copy then is the destination's
own way back: its snapshots, trash or lock. Turn it on, and keep it longer
than you'd take to notice.

## Set up the destination

Run `rclone config` on the server and add two remotes:

1. **The destination**, for example one named `gdrive`, of type `drive` for
   Google Drive. For Google Drive, choose the `drive.file` scope: rclone then sees only the files it
   made, not the rest of the Drive. Dropbox, Google Drive and OneDrive ask you
   to sign in through a browser. On a server without one, connect with
   `ssh -L 53682:127.0.0.1:53682 <server>` before running `rclone config`,
   answer yes to signing in with a browser, and open the link rclone prints
   in the browser of the computer you connected from.
2. **An encrypting remote over it**, named `offsite`, of type `crypt`, with
   `gdrive:inkhold` as its remote (the destination's name, then a folder),
   and both its passwords generated by rclone.

Everything copied through `offsite:` is encrypted before it leaves the
server, names included. Do this for every destination outside your home: a
backup taken with `--include-cred-key` holds the key that protects the
accounts' passwords.

**Keep the two crypt passwords somewhere other than the server**, such as a
password manager. rclone's config file is the only other place that has
them, and without them the copy can't be read.

## Copy after each backup

```sh
rclone copy /srv/inkhold-backup offsite: --immutable \
  --exclude '*.partial/**' --exclude '*.tmp' \
  --exclude '.inkhold-backup.lock' --exclude '.verify-tmp/**'
```

- **`copy`, never `sync`:** a copy only adds. The server's `--keep` removes
  old snapshots from its own folder, and that never reaches the copy.
- **`--immutable`:** a file in the backup folder is written once and never
  changed. If one ever differs from the copy's, rclone refuses it and says
  so, instead of overwriting the good one.
- **The excludes** leave out a snapshot still being written and its working
  files.

Run it once the backup has finished: straight after it in the same cron line
(`inkhold backup create … && rclone copy …`), or a couple of hours later. In
Docker, where the container backs up at 03:00 UTC, run rclone on the host at
05:00. A copy that overlaps a backup is not harmed, but it can miss part of
that night's snapshot until the next copy.

## Copy from another computer instead

To keep the server out of the copy entirely, let a computer at home fetch it.
Give that computer an account on the server that can only read the backup
folder, add an `sftp` remote for the server on that computer, and run the
same `rclone copy` there, the other way round:

```sh
rclone copy server:/srv/inkhold-backup /mnt/inkhold-copy --immutable \
  --exclude '*.partial/**' --exclude '*.tmp' \
  --exclude '.inkhold-backup.lock' --exclude '.verify-tmp/**'
```

The copy never leaves your home, so it needs no encryption.

## Check the copy

Every few months, bring the copy down to a computer with Inkhold and check
it, as a restore would. Do it on a computer other than the server, at least
the first time, with an `offsite` remote set up again from the saved
passwords rather than from the server's config file: a check that passes
there proves the copy opens without the server.

```sh
rclone copy offsite: ~/inkhold-check
inkhold backup verify ~/inkhold-check --deep
```

That downloads the whole library, so don't do it nightly. It is also a
restore rehearsal: [Restore from a backup](@/manual/restore.md) restores from
that folder the same way.

## Trim the copy

Because the copy only adds, its old snapshots pile up. Each one is small,
since the files are stored once for every snapshot. When you want to trim it,
mirror the server's folder once:

```sh
rclone sync /srv/inkhold-backup offsite: --exclude '*.partial/**' \
  --exclude '*.tmp' --exclude '.inkhold-backup.lock' --exclude '.verify-tmp/**'
```

Do this only when the server is sound: a sync copies its mistakes too. The
destination's trash or snapshots keep what it removed for a while.
